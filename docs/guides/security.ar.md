# الأمن والخصوصية

**ينطبق على:** NEXUS V1 `0.1.0` · **الإصدار المدعوم:** `0.1.0` فقط (ما قبل الإصدار؛ لا فروع إصدار).

تصف هذه الصفحة الخصائص الأمنية المنفَّذة، وحدود الثقة المتبقية، وكيف تُبلّغ عن ثغرة. وتتجنب عمداً الادعاءات المطلقة: NEXUS ليس «غير قابل للاختراق»، وسلسلة التدقيق ليست «مانعة للعبث»، و«محلي أولاً» لا يعني أن التطبيق يشفّر البيانات.

---

## 1. المعمارية الأمنية في فقرة

NEXUS تطبيق سطح مكتب محلي أولاً على Windows. تستطيع واجهة React إرسال أوامر مطبوعة فقط عبر حدود IPC في Tauri؛ وتُستنتج الهوية والمستأجر والأدوار والصلاحيات والتصنيف والملكية في Rust. بيانات الأعمال في قاعدة SQLite محلية واحدة داخل نطاق `tenant_id`، ومحمية بفحص تفويض قبل كل أمر محمي. اعتمادات الذكاء الاصطناعي الحساسة مشفّرة بـWindows DPAPI (نطاق المستخدم). وأحداث التدقيق متسلسلة بـSHA-256 وتُقارن بمرساة محلية. ومزوّدو الذكاء الاصطناعي اختياريون وصريحون ومقيّدون بسياسة وجهة صارمة. لا تليمتري ولا مزامنة سحابية ولا نشاط شبكي في الخلفية.

## 2. المصادقة والجلسات

| الخاصية | التنفيذ |
|---|---|
| تجزئة كلمة المرور | Argon2id |
| سياسة كلمة المرور | 12–128 حرفاً، كبير + صغير + رقم + رمز |
| عمر الجلسة (إنتاج) | 12 ساعة |
| ربط الجلسة | استعلام الصلاحية يربط **معرّف الجلسة النشطة بعينها** و`revoked_at` و`expires_at` |
| الإبطال | تسجيل الخروج وتغيير كلمة المرور وإلغاء الجلسات وتعطيل الحساب تسري على الأمر التالي |
| القفل | 5/10/15 محاولة فاشلة ← 60/300/900 ثانية |
| عزل الديمو | هويات وجلسات الديمو تُرفض في وضع الإنتاج عبر `authorization_service` |
| تعداد المستخدمين | المستخدم المجهول يُتحقق منه مقابل تجزئة Argon2id وهمية كي لا يكشف التوقيت وجوده |

## 3. التفويض وعزل المستأجرين

- **كتالوج الصلاحيات** قائمة ثابتة مبنية على `resource:action` (مثل `obligation:create` و`approval:decide` و`user:update` و`integration:credential`).
- **الأدوار الإنتاجية المدمجة:** `TENANT_ADMIN` (كل الصلاحيات)، `CONTRIBUTOR` (قراءات + نقل مهمته + تسجيل دليل)، `REVIEWER` (قراءات + تحقق الأدلة + تحقق الالتزام + قرار الموافقة).
- **بلا تصعيد أدوار:** يرفض الخلف منح دور تتجاوز صلاحياته سلطة المُسنِد، ولا يعدّل المستخدم حسابه أو أدواره.
- **عزل المستأجرين:** كل جدول أعمال يحمل `tenant_id`، والمستودعات تفلتر بالمستأجر النشط، ومشغّلات SQLite ترفض نقل ملكية الأدلة بين المستأجرين. والبحث عبر مستأجر آخر يعيد «غير موجود/مرفوض» دون تسريب السجل.
- **موافقات مستقلة:** لا يقرر الطالب موافقته (`SELF_APPROVAL_FORBIDDEN`)، ولا يقرر مقدّم الدليل حالة التحقق منه (`EVIDENCE_SELF_VERIFICATION_FORBIDDEN`). وهذه قواعد خلفية لا أزرار مخفية.
- **فشل مغلق:** غياب الجلسة أو انتهاؤها أو دور مجهول أو خطأ قاعدة البيانات يعني الرفض، لا السماح الضمني.

## 4. حدود IPC والواجهة

- **117 أمراً مطبوعاً** هي كل سطح الواجهة نحو الخلف. تُحقّق الحمولات بـserde قبل أي منطق أعمال، وتُرفض الحقول المجهولة والأنواع غير الصالحة.
- **القدرات:** `core:default` و`dialog:allow-open` و`dialog:allow-save` فقط. لا صدفة ولا نظام ملفات عام ولا HTTP.
- **CSP:** `default-src 'self'`؛ والسكربتات والأنماط محلية فقط؛ و`connect-src` محصورة في `self` و`ipc:` و`http://ipc.localhost`. ولا خطوط بعيدة ولا CDN ولا `@import` وقت تشغيل.
- **أخطاء آمنة:** تتلقى الواجهة رمز خطأ ثابتاً (`SafeError`) لا رسائل داخلية ولا SQL ولا مسارات.
- الواجهة غير موثوقة للسلطة: لا تختار مستأجراً ولا دوراً ولا قائمة صلاحيات ولا تصنيفاً ولا مالكاً.

## 5. البيانات في حالة السكون

| العنصر | الحماية |
|---|---|
| قاعدة SQLite | ملف محلي في ملف تعريف Windows للمستخدم؛ **غير مشفّرة بواسطة NEXUS** |
| مرساة التدقيق | ملف JSON محلي بجوار القاعدة |
| اعتمادات AI | Windows DPAPI، نطاق المستخدم، لكل مستأجر + مزوّد |
| السجلات | سطور تشغيلية فقط؛ بلا أسرار وبلا حمولات أعمال |
| النسخ الاحتياطية | `VACUUM INTO` + بيان (إصدار المخطط + SHA-256)؛ احمها كالقاعدة نفسها |

> تشفير القرص الكامل وأمن حساب نظام التشغيل مسؤولية المستخدم. ومن يستطيع قراءة ملف تعريف Windows يستطيع قراءة ملف SQLite ما لم توجد حماية إضافية على مستوى النظام (مثل BitLocker).

## 6. سلسلة التدقيق — ما تثبته وما لا تثبته

**ما تكشفه:** تعديل حدث، حذفه، إعادة ترتيبه، تبديل الفاعل/المستأجر، واقتطاع الذيل مقارنةً بـ`audit-anchor.json`. كل حدث يحمل تجزئة السابق وSHA-256 على حمولته، والتحقق يعيد حساب السلسلة كاملة.

**ما لا تكشفه:** من يملك الجهاز بالكامل ويعيد كتابة القاعدة **والمرساة** بشكل متسق. المرساة محلية وليست ختماً زمنياً خارجياً ولا جذر ثقة عتادياً. والتحقق لا يُصلح الاختلاف بصمت؛ السلسلة المكسورة تُعرض مكسورة.

## 7. حدود مزوّدي الذكاء الاصطناعي

- لا مزوّد مفعّل افتراضياً، وكل نداء إجراء مستخدم صريح.
- سياسة الوجهة: HTTPS لغير الحلقي؛ وHTTP فقط على `127.0.0.1`؛ ورفض بيانات الاعتماد في العنوان؛ ورفض المضيفين الخاصين/link-local/الوصفيين؛ وتثبيت DNS بعد التحقق (منع إعادة الربط)؛ وبلا تحويلات؛ وحدود حجم ومهلة.
- المفاتيح تُقرأ من DPAPI لحظة الطلب ولا تعود عبر IPC.
- سجلات الموافقة تربط هوية الوجهة بدقة، وأي تغيير لاحق يُبطل التنفيذ.
- **البيانات لا تغادر الجهاز إلا حين يعدّ المستخدم مزوّداً سحابياً ويشغّله.** ولا يمكن للمنتج منع المستخدم من إرسال بياناته إلى مزوّد يختاره؛ لكن سجل الموافقة والتدقيق يوثّقان القرار.

## 8. أمان التصدير والنسخ الاحتياطي

- التصدير عبر حوار الحفظ الأصلي في Windows.
- يرفض الخلف المسارات النسبية ومجلدات بيانات التطبيق والوجهات غير الآمنة؛ والكتابة ذرّية ومحدودة الحجم؛ وكل تصدير يُنتج حدث تدقيق واحداً.
- تتحقق الاستعادة من البيان وتُبطل مرساة التدقيق صراحةً قبل إعادة التثبيت.

## 9. قيود معروفة (معلنة لا مخفية)

- مرساة التدقيق محلية: التحكم الكامل بالجهاز يتغلب عليها (§6).
- SQLite غير مشفّرة عند السكون بواسطة التطبيق.
- الثنائيات غير موقّعة: بناء V1 `NotSigned`، ولا شهادة توقيع موزّعة.
- لا MFA ولا SSO ولا مزوّد هوية خارجي.
- لم تُجرَ شهادة أمنية ولا اختبار اختراق مستقل. وتقارير V1 تحقق داخلي فقط.
- بعض الاعتماديات تحمل تحذيرات RustSec إعلامية غائبة عن هدف Windows؛ وهي مذكورة في `THIRD_PARTY_NOTICES.md` وملاحظات الإصدار لا مخفية.
- ضوابط حقن التوجيه (prompt injection) تعتمد على نموذج الأدوات والموافقات المحكوم، لا على ضمان أن النموذج غير قابل للتلاعب.

## 10. الإبلاغ عن ثغرة

يُرجى استخدام **الإفصاح الخاص المنسَّق**:

1. **المفضّل:** GitHub Security Advisories («Report a vulnerability») على المستودع `D0shi-Eng/Nexus1`. يبقي التقرير خاصاً وينشئ إصلاحاً متتبَّعاً.
2. إلى أن يصبح المستودع عاماً، استخدم قناة التعاون/الأمن الخاصة في المستودع الخاص مع المشرف؛ ولا تفتح Issue أو PR عاماً يصف الثغرة.
3. ضمّن: الإصدار المتأثر (`0.1.0`)، والأثر، وخطوات إعادة الإنتاج على مساحة **تركيبية أو اختبارية**، ودليلاً بلا بيانات شخصية حقيقية.
4. لا تختبر بيانات مستخدم حقيقية، ولا تُجرِ هندسة اجتماعية أو حجب خدمة أو وصولاً إلى أنظمة لا تملكها.

**التزامنا:** الإقرار بالاستلام، وتتبّع الإصلاح، وإشعارك عند تجهيز إصدار مصحّح. ولا يوجد برنامج مكافآت ولا التزام مالي.

**لا يوجد بريد شخصي منشور.** لا تخترع عنواناً ولا تستخدم واحداً؛ استخدم قناة GitHub أعلاه.

## 11. قواعد تطوير آمنة للمساهمين

- لا تُودِع مفاتيح API ولا رموزاً ولا كلمات مرور ولا مفاتيح خاصة ولا شهادات توقيع ولا ملفات `.env` ولا قواعد بيانات.
- لا تُضف موارد وقت تشغيل بعيدة (CDN، خطوط، سكربتات)؛ فـCSP تمنعها والتوريد المحلي شرط تصميمي.
- أي تغيير في التفويض أو المصادقة أو الجلسات أو القدرات يتطلب اختبار انحدار.
- المسارات المطلقة للمطور (`C:\Users\...` وأسماء المضيفين والحسابات) يجب ألا تظهر في الشيفرة أو الاختبارات أو التوثيق أو رسائل الالتزام.
- عند الشك في حساسية ملف: استبعده من النشر ووثّق السبب.
