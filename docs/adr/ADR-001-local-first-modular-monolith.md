# ADR-001: تطبيق محلي أولاً ببنية Modular Monolith

**الحالة:** مقبول  
**التاريخ:** 16 أغسطس 2026

## السياق

يتطلب NEXUS تطبيق سطح مكتب محلياً أولاً، مع قابلية التوسع لاحقاً لخدمات سحابية متعددة المستأجرين. المجال مترابط بدرجة عالية: الانطباق يعتمد على ملف المؤسسة والمتطلبات، والالتزامات ترتبط بالأدلة والمخاطر والمهام والتدقيق. البدء بخدمات دقيقة سيضيف مصادقة وشبكة ومراقبة واتساقاً موزعاً قبل تثبيت قواعد المجال.

## القرار

سيبدأ المنتج كتطبيق **Tauri 2 + Rust + React + TypeScript** ببنية Modular Monolith. لكل سياق محدود حزم مجال وتطبيق مستقلة، وتنحصر البنية التحتية في محولات خلف منافذ. تظل العقود قابلة للاستخراج إلى خدمات لاحقة، لكن لا توجد عملية أو شبكة مستقلة ما لم يثبت احتياج تشغيلي قابل للقياس.

## البدائل التي روجعت

| البديل | القرار | السبب |
|---|---|---|
| خدمات دقيقة منذ البداية | مرفوض الآن | عبء تشغيلي وأمني كبير قبل تحقق من حدود المجال ونموذج الاستخدام. |
| تطبيق ويب فقط | مرفوض | لا يحقق شرط Local-first وتخزين SQLite المحلي وعمليات سطح المكتب. |
| Electron | مرفوض | لا يطابق اختيار المستخدم الصريح لـTauri 2/Rust. |
| Modular Monolith محلي أولاً | مقبول | أقل تعقيداً، قابل للاختبار، ويحافظ على حدود قابلة للاستخراج. |

## العواقب

تكون المزامنة والسحابة والتكاملات الخارجية محولات اختيارية وليست مسارات إجبارية. يلتزم كل سياق بواجهات ومنافذ محددة، ويمنع استيراد البنية التحتية داخل المجال. أي فصل مستقبلي يجب أن يبدأ من عقد موجود واختبارات تعاقد، لا من نسخ منطق الأعمال.

## معايير إعادة النظر

يعاد تقييم القرار عند تحقق دليل موضوعي مثل استقلال نشر مطلوب، أو معدل عمل خلفي لا يمكن لعميل سطح المكتب تحمله، أو فرق هندسية مستقلة تحتاج حدود ملكية تشغيلية، أو متطلب عزل متعمد بين مناطق بيانات لا يكفي له نموذج الاتصال المحلي/الخادم.
